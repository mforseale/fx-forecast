# Первый аналитический проект: прогноз USD/RUB

Решение от 28 октября 2026 года. Это отдельный учебный проект для портфолио продуктового аналитика; он располагается в `analytics/fx-forecast/` и не входит в приложение Nen. Предыдущие архитектурные документы сохраняются.

## Вопрос и границы

Можно ли по истории официального USD/RUB предсказать следующее наблюдение точнее, чем правилом «следующий курс равен последнему известному»? Первая версия включает загрузку данных, анализ ряда, ARIMA, Prophet, честную проверку качества и небольшой отчёт. Сервисы, Airflow, торговые стратегии и Telegram в этот этап не входят.

Источник — XML API Банка России, валюта `R01235`, фиксированный интервал 2018-01-01 — 2025-12-31. Фиксированный исторический срез обеспечивает воспроизводимость. Сохраняются исходный XML, его SHA-256 и таблица с курсом за одну единицу валюты.

Прогнозируется следующее наблюдение источника, а не следующий рабочий день: даты действия официального курса не совпадают с обычной пятидневной неделей. Выходные не заполняются искусственными значениями. XML не содержит времени публикации; проверка проводится в порядке наблюдений и не является проверкой доступной в реальном времени торговой стратегии.

## Проверка качества

- Последние 180 наблюдений делятся на validation (60) и test (120); всё более раннее — исходное обучение.
- Для каждой точки прогноз строится только по предшествующей истории; окно — последние 750 наблюдений, горизонт — одно наблюдение.
- Небольшая сетка ARIMA и две настройки Prophet сравниваются на каждой пятой точке validation (12 прогнозов). Выбор фиксируется до test; test не используется для настройки. Test оценивается на всех 120 последовательных точках.
- Основная метрика — WAPE: `100 * sum(abs(actual - forecast)) / sum(abs(actual))`. Дополнительные — MAE в рублях и RMSE.
- Baseline — последнее известное значение. Результаты моделей сравниваются на одних и тех же датах.
- Реальные скачки курса сохраняются. Удалять наблюдения из-за большого изменения нельзя: это может скрыть именно те ошибки, которые требуется измерить.
- ADF, ACF и декомпозиция используются для описания обучающей части, а не как доказательство предсказуемости или причин изменения курса. Сезонность заранее не объявляется существующей.
- Если сложная модель уступает baseline, это фиксируется как результат исследования. Победа по точечной метрике не объявляется статистически доказанным преимуществом.

## Архитектура

`XML ЦБ → проверка и нормализация → CSV → временные срезы → rolling backtest → метрики, графики, отчёт и ноутбук`.

Первоначально для отдельного виртуального окружения выбран Python 3.11. Уточнение при реализации: зарегистрированный Python 3.11 отсутствует на диске; вместо него используется доступный Python 3.14 с совместимыми готовыми пакетами. Основные библиотеки: pandas, NumPy, statsmodels, Prophet и matplotlib. Зависимости изолированы от API и frontend Nen. Сценарий запускается одной командой; ноутбук объясняет методику и открывает сохранённые результаты.

Нужны проверки для разбора XML и номинала, дубликатов/невалидных значений, формулы WAPE и отсутствия будущих наблюдений в окнах backtest. Полный запуск подтверждает, что обе модели действительно обучились, а графики и таблицы сформированы.
